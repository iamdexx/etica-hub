# EticaSwap Direct — internal security audit

Scope: `packages/contracts/src/direct/` (`EticaDirectFactory`, `EticaDirectPair`, `EticaDirectERC20`, `EticaDirectLibrary`, `EticaDirectRouter`, `DirectSwapHarvesterAdapter`, `IEticaDirectFactory`) at PR #346. Method: line-by-line review against the audited EticaSwap V2 sources they were derived from (diffs are limited to the gate, the 1.00% fee constants, LP name/symbol and the curated `createPair`), Slither 0.10 (`--exclude-informational --exclude-optimization --exclude-low`), and adversarial Foundry tests in `test/direct/EticaDirect.t.sol` (18 tests).

Nothing is deployed; all fixes below are in the PR.

## Findings

| # | Severity | Finding | Status |
|---|----------|---------|--------|
| 1 | High | Gate bypass via sibling pair: `isAllowed` trusted every venue pair, so a non-staker could call `pair.swap(..., to = otherPair)` and `skim` the output out. | Fixed: pairs are no longer "allowed" accounts; a pair/whitelisted `to` is accepted only when `msg.sender` is whitelisted (the router/harvester doing a hop). `skim(to)` is gated. Test `test_swap_nonStakerCannotParkOutputOnSiblingPair`. |
| 2 | Medium | Non-staker could dump swap output into the whitelisted router/harvester (`to = router`). Funds would be stranded (the router never sweeps its own balance), so no theft, but it let outsiders trade the pair's price and grief. | Fixed by the same rule as #1; router `gated(to)` additionally rejects `to == router` and `to == any pair` (`EDirect: INVALID_TO`). Test `test_gate_venueContractsAreNotRecipientsForOutsiders`. |
| 3 | Medium | `EticaDirectRouter._addLiquidity` called `pairCreationFee()` / `etx()` on a factory without them, so liquidity could never be added to an unopened pair (revert instead of create). | Fixed: pairs are curated, the router requires the pair to exist (`EDirect: NO_PAIR`). Test `test_addLiquidity_unopenedPairReverts`. |
| 4 | Low | Fee LP of a direct pair whose token has no ETX hub pool cannot be harvested until that hub pool exists (adapter sells every leg through the hub). No loss: LP waits in the adapter. | Accepted; curation rule documented in `docs/ETICASWAP_DIRECT.md`. |
| 5 | Low | Harvest MEV: the keeper supplies `minEtxOut*` / `minPolOut*`; a zero plan would let a sandwicher take the harvest. | Accepted by design (keeper-only, mirrors `TreasuryHarvester`); the keeper quotes a block earlier and never submits zero min-outs. Enforced operationally, not on-chain. |
| 6 | Low | POL buyback deposits the two legs half/half by ETX value; the pair's ratio decides how much LP mints and the remainder is left in the pair as reserves (donated to all LPs, incl. the dead-address POL). | Accepted; documented in the adapter. |
| 7 | Info | Gate is a balance check at execution time. A wallet can buy stETX, trade, and sell stETX in one transaction. This is intended: the gate is "stake ETX to use direct routes", and the round-trip costs stableswap fees. There is no flash-loan source for stETX. | Accepted. |
| 8 | Info | Admin surface: `feeToSetter` (treasury) can change `minStEtx` (incl. to brick the venue), whitelist, trusted creators and `feeTo`; adapter owner can `rescue` tokens sitting in the adapter (incl. unharvested fee LP) and change sinks/split. Single-key trust identical to the rest of the protocol. | Accepted; move `feeToSetter`/owner to the multisig when one exists. |
| 10 | Low | Fee tiers (added after the first pass): because the pair can only see `to`, the router passes its own `msg.sender` as `trader` to `swapFor`. Only whitelisted routers may call it and `trader` must pass the gate, so a non-staker cannot borrow a staker's tier and no wallet is billed at another wallet's discount without signing; `setBaseFeeBps` cannot drop below the first tier so more stETX never costs more. Tier reads are balance snapshots, so a wallet can borrow stETX for one tx to buy a cheaper tier — same trust model as the gate (#7). | Accepted; tests `test_fee_*`, `test_swap_pairChargesTraderTier`, `test_swap_routerPricesEgazUnwrapAtTraderTier`, `test_swapFor_onlyWhitelistedCallerAndStakerTrader`. |
| 9 | Info | LP tokens are freely transferable; a non-staker can hold direct LP but cannot `burn` it (gated). | Accepted. |

## Addendum — hub metapairs (`EticaDirectMetaPair`, `createMetaPair`, adapter in-kind harvest)

Threat model: the window must not be drainable and must not let a trader settle against its reported reserves. 14 tests in `test/direct/EticaDirectMetaPair.t.sol` incl. a fuzzed "hub LP never decreases" invariant.

| # | Severity | Finding | Status |
|---|----------|---------|--------|
| M1 | — | Drain paths: the hub LP has no transfer or burn path (`burn` reverts, no owner, no rescue); `skim` moves only loose `token0`/`token1`/ETX and only to the fee sink; swap output is only ever the hub's return for the trader's own input (`_hubSwap(..., to)`), never a balance of the window. | Verified by design + `testFuzz_hubLpNeverDecreases`, `test_skim_onlyToFeeSink_hubLpUntouched`, `test_burn_alwaysReverts_liquidityLocked`. |
| M2 | Low | Reported reserves are a read-only mirror of the hub; a sandwicher can move a hub pool for one block so the window reports a skewed cross price. Nothing settles against it, so the only effect is a wrong `Sync` for that block. | Accepted; `sync()` is permissionless so keepers republish. A TWAP sanity check can be added if an indexer needs it. |
| M3 | Low | `mint` is for POL seeding: half-swaps and `addLiquidity` use zero min-outs inside the window, so a sandwicher can tax a deposit. `mint` is restricted to `feeToSetter` and whitelisted contracts (seeder, harvester), so a third party cannot be lured into a locked deposit; nothing is withdrawable, so there is no gain beyond that tax. | Accepted; seed in small clips, harvest with the keeper's own tx ordering. |
| M4 | Info | Hub swap fee is paid twice per window trade (two hops) on top of the tier fee; quotes via `quoteOut` include both. A constant-product quote off `getReserves` would be wrong (window reserves ≠ settlement depth). | Documented; the Direct router does not route through windows. |
| M5 | Info | Windows report value, not raw balances: the two sides are each half the window's ETX value, so an aggregator summing TVL across the hub pool and the window double-counts. | Documented. |
| M6 | Medium | **Fee-tier borrowing via `swap(to)`** (metapair and plain pair). The V2-shaped `swap` priced the trade at the *recipient's* tier and gated only the recipient, so a 3%-tier wallet could pre-pay a pair and name a 0.1%-tier wallet as `to` to trade at the whale's discount, and a non-staker could trade at all by naming a staker. Same class as the #347 router finding; the router (`swapFor`) was fixed, the raw pair entry point was not. | Fixed: `swap` now requires `isAllowed(msg.sender)` and bills `feeBpsFor(msg.sender)`; `_requireAllowed(to)` still applies. `test_swap_billsCallerTierNotRecipient`. |
| M7 | Low | **Harvest bricked by dust.** `_payTreasury` swapped the treasury slice to `treasuryToken` unconditionally; a slice too small to buy one unit reverts in V2 (`INSUFFICIENT_OUTPUT_AMOUNT`) and takes the whole harvest with it (same pattern already guarded in `_toEtx`). | Fixed: zero-quote slices are paid in ETX. `test_harvest_treasuryDustPaidInEtxNotReverted`. |
| M8 | Low | **Shared-leg windows lose POL.** Two windows sharing a token (EGAZ/USDC.e and ETI/USDC.e) forward fees in the same USDC.e; the first plan sold the entire balance, the second saw `0/0` and was skipped from the POL split. | Fixed: a listed window always counts for the POL split (the keeper decides which windows to list). `test_harvest_twoWindowsSharingLegBothGetPol`. |
| M9 | Info | Admin surface: `createMetaPair` trusts the `hubRouter` argument (reads `factory()`/`WEGAZ_TOKEN()` from it, settles every trade through it) and `setTreasuryToken` accepts any token; both are `feeToSetter`/owner-only one-shot settings. Rogue `deploy()` on the deployer yields an uninitialised window the factory never registers. `rescue` on the adapter can move raw fee tokens and window shares (non-redeemable), never hub LP.  Mitigation shipped: `UnanimousMultisig` (2-of-2 treasury + second signer) takes over `feeToSetter` and harvester ownership after launch; a guardian key can only pause. | Accepted (single-key admin, as in F-L3). |
| M10 | Info | `_update` reverts with `ESwap: OVERFLOW` if a reported reserve exceeds `uint112`; that needs a hub pool skewed by ~10^11×, unreachable under constant product with real reserves. `sync`/`swap` would pause, nothing moves. | Accepted. |
| M11 | Hardening | **Guardian circuit breaker + retire/replace.** Added `guardian` (pause-only), `pauseSwaps`/`unpauseSwaps` (setter-only unpause), `swapsOpen(pair)` consulted by every swap entry point, and `retirePair` (swaps off, `getPair` cleared for a replacement, harvest keeps working). Pause/retire never touch balances or hub LP, so the guardian key is not a drain vector; worst case is a swap-only DoS, bounded to `guardianPauseDuration` (7 days, setter-tunable) when the guardian key is the one pausing; a setter pause holds until `unpauseSwaps`. Off-chain, `apps/direct-watcher` watches LP monotonicity, admin settings, reserve/hub price agreement and large swaps, and auto-pauses on critical findings. | `test_guardian_canOnlyPause_setterUnpauses_mintSkimSyncHarvestStillWork`, `test_guardianPause_lapsesAfterDuration_setterPauseHolds`, `test_retirePair_blocksSwaps_allowsReplacement_keepsHarvest`. |

## Slither triage

All remaining medium findings are the inherited Uniswap V2 patterns and are protected the same way as in V2 / EticaSwap:

- `reentrancy-no-eth` in `mint`/`burn`/`swap`/`skim`/`createPair`: every pair entry point runs under the `lock` mutex; `createPair` only calls the pair it just deployed.
- `unchecked-transfer` in `removeLiquidity` (`pair.transferFrom`): `EticaDirectERC20.transferFrom` reverts on insufficient balance/allowance, it never returns false.
- `weak-prng` on `block.timestamp % 2**32`: TWAP timestamp wrap, not randomness.
- `divide-before-multiply` in `harvest`: intentional, computes the per-pair rounding dust sent to treasury.
- `incorrect-equality` on `== 0` guards: zero-amount short-circuits.

Metapair pass (Slither 0.11, `src/direct`, 96 results, 0 high): `reentrancy-benign`/`reentrancy-events` in `createMetaPair` (writes after `deploy`/`initialize` on the pair it just created; `initialize` is factory-only) and in `EticaDirectMetaPair._swap` (event after the fee `safeTransfer`; entry points hold `lock`, and the only external targets are the immutable hub router/pairs and the fee sink); `missing-inheritance` (pairs implement the V2 shape without declaring `IEticaDirectPair`, by design); `unindexed-event-address` on `MetaPairDeployerSet`; `cyclomatic-complexity` on `harvest`. No new finding class.

## Invariants covered by tests

- Only `feeToSetter`/trusted creators open pairs; no ETX rule, no creation fee.
- `isAllowed`: whitelist, `minStEtx == 0`, stETX balance; pairs are never allowed accounts.
- Add/remove liquidity and swaps through the router and directly on the pair require a staker recipient; transferring stETX away revokes access; router/pair/adapter cannot be used as recipients by outsiders.
- Swap fee is tiered by the trader's stETX balance (`feeBpsFor`, base 3.00%, ladder non-increasing, ≤10%): a cheaper tier's output fails the K check; router quotes match the pair; EGAZ-unwrap and multi-hop hops are priced at the initiating wallet's tier via `swapFor`; `swapFor` is whitelisted-caller-only and the named trader must pass the gate.
- V2 `Sync`/`Swap`/`PairCreated` events for indexers.
- Harvest: 10% stETX (NAV rises), 10% farms, 40% POL LP burned to `0xdead`, 40% + dust to treasury; adapter ends with zero ETX and zero LP; keeper-only; venue pairs only.
- Metapair: `swap`/`swapExactIn` bill the caller's tier and gate the caller; the recipient's tier is never used (`swapFor` is router-only). Harvest pays dust slices in ETX, never reverts on a zero quote; every listed window gets an equal POL share.
